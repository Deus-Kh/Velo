## Архитектура приложения

Архитура приложения построена по многоуровневому принципу, что обеспечивает разделение ответственности, масштабируемость и удобство сопровождения.

---

### 2.1 UI Layer (Пользовательский интерфейс)

Реализован с использованием React Native.

Функции:
- отображение данных;
- обработка пользовательских действий;
- передача событий в слой бизнес-логики.

UI не содержит сложной логики и не взаимодействует напрямую с криптографией.

---

### 2.2 Application Layer (Бизнес-логика)

Выступает посредником между UI и нижележащими слоями.

Функции:
- обработка пользовательских сценариев;
- управление состоянием приложения;
- координация работы сервисов.

---

### 2.3 Сервисный уровень

Включает специализированные сервисы:

#### Chat Service
- отправка и получение сообщений;
- взаимодействие с криптографическим слоем;
- обработка статусов сообщений.

#### Auth Service
- регистрация и авторизация пользователей;
- управление сессией.

#### User Service
- поиск пользователей;
- управление профилем.

---

### 2.4 Crypto Layer (Криптографический слой)

Ключевой компонент системы безопасности.

Функции:
- установление защищённого соединения (X3DH);
- шифрование и дешифрование сообщений;
- хэширование (SHA-256);
- управление ключами.

Криптографический слой изолирован от UI, что повышает безопасность и упрощает тестирование.

---

### 2.5 Data Layer (Хранение данных)

Отвечает за локальное хранение информации:
- сообщения;
- ключи;
- пользовательские данные.

Может использоваться локальная база данных или защищённое хранилище.

---

### 2.6 Network Layer (Сетевой уровень)

Обеспечивает передачу данных между клиентами.

Функции:
- отправка сообщений;
- получение данных;
- синхронизация состояния.

Важно, что передаваемые данные уже зашифрованы на уровне клиента.

---

## 3. Поток данных

Процесс отправки сообщения:

1. Пользователь вводит сообщение в UI;
2. событие передаётся в Chat Service;
3. сообщение шифруется в Crypto Layer;
4. зашифрованные данные передаются в Network Layer;
5. сообщение доставляется получателю;
6. на стороне получателя происходит дешифрование;
7. сообщение отображается в UI.

---

## 4. Безопасность архитектуры

Ключевые особенности:
- изоляция криптографического слоя;
- отсутствие передачи незашифрованных данных;
- локальное хранение ключей;
- возможность проверки подлинности пользователей.

---

## 5. Итоги

Предложенная архитектура:
- обеспечивает безопасность передачи данных;
- разделяет ответственность между слоями;
- упрощает масштабирование;
- соответствует современным принципам разработки мобильных приложений.
